# Native dependency packaging in generated applications

Generated applications now declare platform runtimes as versioned dependencies
instead of loose implementation files:

- iOS generates `ios/Package.swift`, whose binary target resolves
  `ios/.gonative/GoNativeKit.xcframework`.
- Android resolves `dev.gonative:gonative-runtime:0.1.0` from the generated
  `android/.gonative/m2` Maven repository.
- `gonative.yaml` records the framework, mutation protocol, measurement protocol,
  and minimum platform versions used by the application.

`gonative build` refreshes both `.gonative` dependency caches before compiling.
These directories are generated and must not be committed. Application launchers,
native project settings, resources, and extension points remain visible and owned
by the application developer.

Existing generated applications should regenerate their native build metadata or
make the following changes:

1. Replace direct `files("libs/gonative-runtime.aar")` dependencies with the Maven
   coordinate above and add `android/.gonative/m2` to dependency repositories.
2. Add the generated `ios/Package.swift` and let `gonative build ios` populate its
   local binary target.
3. Add `gonative.yaml` and pin protocol versions 10 and 2.
