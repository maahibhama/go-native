# Migrating custom hosts to v0.3 text and input

Mutation protocol v10 is not wire-compatible with v9. After the existing interaction-payload length and bytes, and before the typed-style record, decode these little-endian fields in declaration order:

1. `uint8 textWrap`, `uint8 textOverflow`, `uint32 maxLines`, `uint8 selectable`
2. `uint32 richTextLength` and rich-text bytes, then `uint64 onLink`
3. `uint32 placeholderLength` and UTF-8 bytes
4. `uint8 inputMode`, `uint8 inputKind`, `uint8 returnKey`, `uint8 capitalization`, `uint8 autoCorrect`
5. `uint8 secure`, `uint8 multiline`, `uint8 readOnly`, `uint8 validationState`
6. `uint32 errorTextLength` and UTF-8 bytes
7. `int32 selectionStart`, `int32 selectionEnd`, `int32 maxLength`
8. `uint64 onSubmit`, `uint64 onSelection`

Zero `maxLines` and `maxLength` mean unlimited. Selection `{-1,-1}` leaves selection native-owned. Selection offsets use UTF-16 code units. `inputMode == 0` is controlled and `inputMode == 1` is initialized once then native-owned. String and rich-text fields are limited to 1 MiB; the entire mutation batch remains limited to 16 MiB.

The rich-text payload starts with `uint16 version == 1` and `uint32 spanCount`. Each span contains text and link as length-prefixed UTF-8, `float32 fontSize`, `uint16 fontWeight`, `uint8 flags` (underline bit 0, italic bit 1), `uint8 hasColor`, and four RGBA bytes.

Existing action and string-value callbacks carry submit and link events. Selection requires one new callback carrying only `uint64 handlerID`, `int32 start`, and `int32 end`; forward it to `Runtime.DispatchSelection`.

Native measurement protocol v2 adds the following request fields after text and image source, before typed style: `uint8 textWrap`, `uint8 textOverflow`, `uint32 maxLines`, `uint8 selectable`, length-prefixed rich-text bytes, length-prefixed placeholder UTF-8, `uint8 inputKind`, `uint8 secure`, `uint8 multiline`, and `int32 maxLength`. Measurement result bodies are unchanged, but their header version is also 2.
